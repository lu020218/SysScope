# SysScope 需求文档

> 版本：v0.1（需求对齐稿）　日期：2026-08-12

## 1. 产品定位

SysScope 是一款 Windows 桌面系统状态监控工具，以独立窗口的图表面板形式，实时展示
CPU、GPU、内存、FPS 等关键指标，并支持将监控数据导出为报告。

- 产品形态：桌面应用（实时曲线图表 + 仪表盘面板）
- 目标平台：Windows 10/11（x64）
- 技术栈：Rust + Tauri（前端使用 Web 技术渲染图表）

## 2. 监控指标

### 2.1 CPU
- 总占用率（%）及每核心占用率
- 当前频率（MHz）
- 温度（℃，视传感器可用性）
- 进程级 Top-N CPU 占用（可选，二期）

### 2.2 GPU
- GPU 占用率（%）
- 显存占用 / 总量（MB）
- 温度（℃）
- 功耗（W，视硬件支持）
- 优先支持 NVIDIA（NVML）；AMD/Intel 核显通过 Windows 性能计数器（DXGI/PDH）降级支持

### 2.3 内存
- 物理内存：已用 / 可用 / 总量（MB、%）
- 提交内存（Commit Charge）
- 进程级 Top-N 内存占用（可选，二期）

### 2.4 网络（2026-08-12 需求补充）
- 各网络接口上行 / 下行速率（实时，按采样间隔差分）
- 累计收发流量（系统启动以来）
- 过滤回环接口与无流量接口，多接口按当前速率排序展示

### 2.5 FPS
- 监控范围：**任意前台应用**——自动跟踪当前前台窗口对应进程的帧率
- 采集方案：基于 ETW（Event Tracing for Windows）捕获 DXGI/D3D Present 事件
  （PresentMon 同源方案），需要**管理员权限**运行
- 指标：实时 FPS、平均 FPS、1% Low / 0.1% Low、帧时间（ms）
- 无渲染活动的窗口（如纯文本应用）显示"无帧数据"而非 0
- 展示形态（2026-08-12 变更）：FPS 不在主面板卡片展示，改为独立悬浮窗（OSD）——
  无边框、置顶、半透明、可拖动、不占任务栏；悬浮窗同时显示 CPU / GPU / 内存
  占用率简略值；主窗口提供悬浮窗显隐开关

## 3. 实时展示

- 刷新率：默认 1 秒，可配置（0.5s / 1s / 2s / 5s）
- 每项指标提供实时数值 + 滚动时间窗曲线图（默认展示最近 60s / 5min / 30min 可切换）
- 仪表盘概览页 + 各指标详情页
- 窗口支持置顶（Always on Top）与紧凑模式
- 支持最小化到系统托盘常驻，托盘菜单提供快速开关（显示面板 / 开始记录 / 退出）
- ~~支持开机自启动（默认关闭，设置中可开启；自启时以托盘形式静默启动）~~
  **（2026-08-14 移除）**：程序改为强制管理员权限运行后，Windows 不允许
  要求提权的程序通过普通启动项自启，该开关无法生效。已从设置界面移除，
  改由用户在「任务计划程序」中创建"以最高权限运行"的任务实现
  （程序保留 `--minimized` 参数支持静默启动到托盘）
- 指标阈值高亮：占用率 / 温度超过阈值时曲线与数值变色提示（阈值可配置）

## 4. 数据记录与监控报告

### 4.1 记录
- 支持手动"开始记录 / 停止记录"一段监控会话
- 采样数据落盘（本地存储，建议 SQLite 或按会话分文件）
- 数据保留策略：默认保留最近 N 天 / N 个会话，可配置

### 4.2 报告输出（三种格式均支持）
1. **HTML 报告**：自包含单文件，内嵌交互式历史曲线图表，适合查看与分享
2. **CSV / JSON 原始数据**：导出会话内全部采样点，便于 Excel 等二次分析
3. **统计摘要（Markdown / PDF）**：会话时长、各指标均值 / 峰值 / 最低值、
   FPS 1% Low、超阈值异常时段标注

## 5. 非功能需求

- 自身资源占用（2026-08-14 依实测修订，口径为**整个进程树**，
  含 WebView2 渲染/GPU/服务子进程）：
  - 采集端 CPU：常态 < 2%（单次采样约 20ms，1s 档占约 2% 时间片）
  - 内存：**托盘常驻 ≤ 150MB**（隐藏主面板后自动释放渲染内存）；
    **主面板显示时 ≤ 500MB**（实测约 490MB，其中 Rust 后端仅约 70MB，
    其余为 Chromium/WebView2 运行时固定开销，属架构成本而非缺陷）
  - 说明：原定"内存 < 150MB"未区分显示/常驻状态，且仅统计了主进程，
    与 WebView2 架构现实不符，故按上述实测值修订
- 采集异常（传感器不可用、驱动缺失）时优雅降级，对应指标显示"不可用"而非崩溃
- FPS 采集需管理员权限：无权限时其余指标正常工作，FPS 卡片提示"以管理员身份重启以启用"
- 硬件信息清单：CPU（步进/缓存/微码/指令集/虚拟化）、内存（逐条型号/速率/插槽）、
  显卡（驱动/VBIOS/PCIe 链路）、磁盘（介质/总线/固件/健康度）、网卡（MAC/IP/链路）、
  主板与 BIOS、系统版本。数据静态不变，首次请求时采集一次并永久缓存，
  不进入采样循环也不拖慢启动
  - 隐私：序列号与 MAC 在界面完整显示，导出报告时默认只保留后 4 位，
    可在设置中开启完整输出。脱敏在后端执行，使其成为不变式而非调用方约定
- 界面语言：简体中文 + 英文。首次启动跟随 Windows 显示语言，可在设置中切换；
  报告随导出时的界面语言，CSV/JSON 的列名与字段名固定英文以免破坏下游解析
  - 说明：原定"中文（一期），预留 i18n 结构"已落地为完整双语支持

## 6. 技术方案要点（Rust 生态）

| 能力 | 方案 |
|---|---|
| CPU / 内存 / 进程 | `sysinfo` crate + Windows PDH 性能计数器 |
| NVIDIA GPU | `nvml-wrapper`（NVML 官方接口） |
| AMD / Intel GPU | WMI 格式化性能计数器（`GPUEngine` / `GPUAdapterMemory`，与 PDH 同源数据） |
| 温度 | 首选 WMI / 原生接口（`wmi` crate、NVML 自带 GPU 温度）；覆盖不足时以**进程内动态库**方式集成 LibreHardwareMonitor（见下） |
| FPS | ETW 实时会话（`ferrisetw` crate 订阅 DXGI/DxgKrnl Present 事件） |
| 前端图表 | Tauri WebView + 轻量图表库（如 uPlot / ECharts） |
| 本地存储 | SQLite（`rusqlite`） |

### 温度采集备选方案：LibreHardwareMonitor 库级集成

约束：以动态库/静态库方式进程内集成，不引入独立后台进程或 Windows 服务。

- **方案 B1（首选，已于 2026-08-12 落地）**：用 .NET NativeAOT 将 LibreHardwareMonitorLib
  编译为原生 DLL，导出 C ABI 接口（init / cpu_temp / last_error / shutdown），Rust 侧
  通过 FFI 加载调用。产物为单个原生 DLL（约 6MB），无需目标机安装 .NET 运行时。
  实施备注：本机 ACPI 热区（MSAcpi_ThermalZoneTemperature）为固定占位值已验证不可用；
  NativeAOT 需 rd.xml 强制生成 DeviceIOControl 泛型封送元数据（见 sensor-bridge/rd.xml）
- **方案 B2（B1 受阻时）**：通过 `hostfxr` 在 SysScope 进程内托管 .NET 运行时加载
  LibreHardwareMonitorLib（self-contained 部署），仍为进程内库调用
- 注意：CPU 温度等底层传感器访问依赖其内核驱动（PawnIO/WinRing0），
  该驱动随库加载，同样需要管理员权限——与 FPS 的 ETW 采集提权要求一致，可合并处理
- .NET 静态库链接不可行，故"静态库"路径不适用，统一采用动态库形态

## 7. 里程碑建议

1. **M1 骨架**：Tauri 应用框架 + CPU / 内存实时采集与曲线展示
2. **M2 GPU**：NVML + PDH 双路 GPU 指标接入
3. **M3 FPS**：ETW 帧率采集 + 前台窗口自动跟踪
4. **M4 记录与报告**：会话记录、SQLite 落盘、三种格式报告导出
5. **M5 打磨**：阈值告警、紧凑模式、配置项、降级与异常处理完善
6. **M6 双语**（2026-08-20 完成）：中英文界面与报告，两道 CI 检查保证翻译不漏
7. **M7 硬件清单**（2026-08-20 完成）：静态硬件信息面板、复制为文本、报告集成与脱敏
